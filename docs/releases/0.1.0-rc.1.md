# Proposed v0.1.0-rc.1 release notes

Status: prepared for review, not tagged or published. This is a release candidate
for evaluation, not a stable v1 release or a production deployment certification.

## Included

- Authoritative-correct existence queries: safe Bloom negatives can avoid a
  datastore lookup; positives and uncertain infrastructure state use the
  authoritative source.
- Framework-neutral Core, contracts and lifecycle/application services with
  Memory reference implementations and atomic stock-Redis persistence.
- Managed sizing, semantic fingerprints, streaming build/verification and
  explicit generation activation.
- Coordinated prepared writes, explicit adoption, online rebuild/abort and
  evidence-bound recovery. Unknown authoritative outcomes retain their leases.
- Laravel configuration, automatic provider discovery, facade, validation
  adapters and lifecycle/coordination/diagnostic commands.
- Read-only status and doctor diagnostics, with opt-in lease inspection that
  rejects inconsistent counters or lease records without repairing storage.

## Compatibility and verification

The declared runtime floor is PHP 8.3 with Laravel 12 or 13. The deep CI matrix
covers PHP 8.3/8.4/8.5 across both Laravel majors plus minimum dependencies.
Each of the seven environments passed 1,064 full tests / 8,304 assertions,
including live Redis, dependency auditing and package discovery at the recorded
candidate in the [release readiness record](../verification/2026-10-05-release-readiness.md).

Distribution verification covers source export exclusions, a real GitHub commit
ZIP and production-only Composer dist installation. Consumer bootstrap is
verified on PHP 8.4/Laravel 13 with Memory; live-Redis behavior has separate
integration evidence. These are different evidence tracks.

## Integration requirements

Memory is a test/development backend. Redis is the planned production backend.
Before trusting optimized negatives, establish the authoritative-set contract,
semantic identity and activation verification, and meet the documented Redis
durability/topology requirements.

For mutable coordinated filters, every membership-entry writer must participate
in the prepared-write protocol. Brownfield adoption requires an external
quiescent handoff. Recovery requires evidence of the authoritative outcome;
there is no automatic timeout release or force recovery.

Read [Laravel coordination and recovery](../architecture/laravel-coordination.md)
and [coordination diagnostics](../architecture/coordination-diagnostics.md)
before enabling coordinated optimization.

## Boundaries

No stable security-support window is promised for this candidate. Report unsafe
lookup bypass or other exploitable correctness failures through
[private vulnerability reporting](https://github.com/kefyusuf/laravel-bloom-gate/security/advisories/new).

The candidate does not certify a specific production deployment, Redis Cluster
runtime support, external authoritative history completeness, or performance
improvements for an unmeasured workload. Packagist indexing remains unobserved.
The Composer dist check consumes a ZIP downloaded to a local file; it does not
verify Composer's remote transport.
