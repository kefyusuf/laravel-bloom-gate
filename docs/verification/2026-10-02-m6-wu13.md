## Invariant review

ADR-0041, ADR-0042 and ADR-0043 remain unchanged. The final implementation keeps:

- stable tokens before remote operations, immutable epoch/target bindings, all
  target pre-adds before durable PREPARED authority, and terminal release;
- both ACQUIRED and PREPARED leases active until a known outcome permits release;
- cleanup uncertainty separate from authoritative transaction outcomes;
- no TTL, destructor release, automatic lease expiry, force recovery or de-adoption;
- owner-first adoption, explicit brownfield handoff, expected-control fencing and
  permanent legacy mutation fencing after adoption;
- atomic pair observations and opposite-revision CAS checks in persistence,
  with lifecycle legality and workflow phase policy owned by Application;
- publication before drain/reconciliation, fresh verification before promotion,
  control promotion before target contraction, and old-epoch drain before completion;
- durable abort progress, candidate retirement only after relevant drains, and
  promotion-winning recovery without reversal;
- read-only diagnostics whose enumeration/count observations never authorize a drain;
- write/lifecycle fail-closed behavior and existing query fail-open fallback.

Laravel adapters validate input, resolve services, poll guarded workflow progress,
and present results. They do not implement Redis atomicity or lifecycle policy.
Genuinely unadopted filters retain the M5 path. Adoption does not alter the
`preadd-v1` semantic identity or enroll raw external database writers.

## Documentation and verification boundary

The README and canonical overview, consistency, lifecycle, Redis foundation,
keyspace and Laravel operation documents now reflect implemented M6 behavior.
Historical WU reports and accepted ADRs remain as the evidence trail.

Race/crash tests establish protocol ordering and recovery at selected boundaries;
they do not kill Redis, establish hardware power-loss durability, or detect a
full historical rollback that erases all local adoption evidence. C20 remains the
accepted external operational-history boundary. Writer participation, brownfield
handoff and the declared Redis production profile remain externally established.

Redis Sentinel/Cluster runtime support, replica trusted negatives, CDC/outbox
synchronization, automated retention/purge and automatic external writer enrollment
are not shipped by M6. This run verifies the stated PHP/Laravel/Redis environment;
the separate release workflow remains responsible for the broader compatibility
and minimum-dependency gates before publication.
