# M6 WU-12 race and crash verification — 2026-10-02

Baseline: `main@d2f95878f43af1dca5f7e61acf6d1fdb1afd9954` plus verified
WU-10/WU-11 workspace changes. No production protocol changes were needed.

## Method and results

The new tests execute the same Application services and atomic persistence ports
against Memory and live Redis. Barriers select a deterministic operation order;
lost acknowledgements are injected after the real operation persists. Rebuild
services are recreated between calls while persisted state and Bloom storage
survive. These simulate process interruption at explicit protocol boundaries;
they do not kill Redis or establish hardware power-loss durability.

Twenty-one additional test cases cover five writer interruption points, ten
rebuild/abort interruption or coordinator race points, and six persistence
race/recovery cases. Each scenario must reach its intended boundary before its
recovery assertions can pass. Reconciliation retries check actual Bloom
membership for every authoritative value after completion. An old prepared
dual-target lease holds post-promotion completion and abort retirement until
explicit release; neither service recreation nor diagnostics clears it.

Environment: PHP 8.4.26, Laravel 13.34.0, Pest 4.7.8, Redis 8.10.2, isolated
Docker containers, Git-equivalent LF PHP source copies.
